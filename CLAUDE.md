## Project Overview

This is the documentation website for **formsflow.ai** — an enterprise form and workflow management platform. The site is built with **Docusaurus 3.7.0** and deployed to GitHub Pages on push to the `develop` branch.

## Commands

```bash
npm start          # Start local dev server (localhost:3000)
npm run build      # Build static site for production
npm run serve      # Serve the built site locally
npm run clear      # Clear Docusaurus cache (use when builds behave unexpectedly)
```

**Versioning:**
```bash
npm run docusaurus docs:version 8.x   # Freeze the v8 set — only when v9 docs start (see Versioning below)
```

## Architecture

```
/
├── docs/                   # v8 documentation set (default version, label 8.x) — v8-only pages
│   ├── index.md            # v8 landing page (slug /)
│   └── <feature>/          # One folder per feature, generated by tools/docs-pipeline/
├── versioned_docs/         # Frozen snapshots — do NOT edit (v7.0.0, v6.0.2)
├── versioned_sidebars/     # Auto-generated sidebars for each frozen version
├── versions.json           # List of released versions
├── blog/                   # Blog posts
├── src/
│   ├── components/         # Custom React components
│   ├── css/custom.css      # Global style overrides
│   └── pages/              # Non-doc standalone pages
├── static/                 # Images and other static assets
├── docusaurus.config.js    # Site config (title, navbar, versioning, plugins)
└── sidebars.js             # Sidebar is auto-generated from docs/ file structure
```

### Key architectural points

- **Sidebar is automatic**: `sidebars.js` uses `autogenerated` — sidebar order comes from frontmatter `sidebar_position` fields in markdown files, not from `sidebars.js` itself.
- **Versioning**: `docs/` is the v8 set and the default version (`lastVersion: 'current'`, label 8.x). It is not copied per 8.x minor release; pages carry an "Added in 8.x" label instead. 7.0.0 and 6.0.2 are frozen in `versioned_docs/`; never edit them. Old root links to v7 pages redirect to `/7.0.0/...` through `@docusaurus/plugin-client-redirects` (production build only, not `npm start`).
- **Broken links fail the build**: `docusaurus.config.js` sets `onBrokenLinks: 'throw'` — fix all broken internal links before merging.
- **Node ≥18 required**: Matches the CI environment (GitHub Actions uses Node 18).

## Deployment

Pushing to `develop` triggers `.github/workflows/pages.yml`, which runs `npm run build` and publishes the output to GitHub Pages automatically. No manual deploy step needed.

## Generated feature pages (docs pipeline)

- Some feature folders in `docs/` (from 8.4: offline-submissions, ai-assisted-submissions, application-styling, form-governance) are generated by `tools/docs-pipeline/` from the product team's action inventory. Read `tools/docs-pipeline/README.md` before changing them. Fix problems in the pipeline's skills or the inventory, then regenerate, rather than hand-editing generated pages. `reference.md` in each feature folder is fully generated.
- The pipeline publishes only into `docs/` and adds each page's "Added in" label from the feature's `addedIn` in `config.json`. Don't run `docs:version` for 8.x minor releases.
- Never commit the inventory CSV or anything under `tools/docs-pipeline/build/`: they carry internal sources.
