## Project Overview

This is the documentation website for **formsflow.ai** — an enterprise form and workflow management platform. The site is built with **Docusaurus 3.7.0** and deployed to GitHub Pages on push to the `develop` branch.

## Commands

```bash
npm start          # Start local dev server (localhost:3000)
npm run build      # Build static site for production
npm run serve      # Serve the built site locally
npm run clear      # Clear Docusaurus cache (use when builds behave unexpectedly)
```

**Versioning:**
```bash
npm run docusaurus docs:version 8.0.0   # Snapshot current docs/ as a new version
```

## Architecture

```
/
├── docs/                   # Current (unreleased) docs — edit these for new features
│   ├── Features/           # Feature-level documentation
│   ├── general-information/ # Installation, setup, configuration guides
│   └── features-premium/   # Premium feature docs
├── versioned_docs/         # Frozen snapshots — do NOT edit (v7.0.0, v6.0.2)
├── versioned_sidebars/     # Auto-generated sidebars for each frozen version
├── versions.json           # List of released versions
├── blog/                   # Blog posts
├── src/
│   ├── components/         # Custom React components
│   ├── css/custom.css      # Global style overrides
│   └── pages/              # Non-doc standalone pages
├── static/                 # Images and other static assets
├── docusaurus.config.js    # Site config (title, navbar, versioning, plugins)
└── sidebars.js             # Sidebar is auto-generated from docs/ file structure
```

### Key architectural points

- **Sidebar is automatic**: `sidebars.js` uses `autogenerated` — sidebar order comes from frontmatter `sidebar_position` fields in markdown files, not from `sidebars.js` itself.
- **Versioning**: `docs/` holds the next/unreleased content. Running `docs:version` freezes a snapshot into `versioned_docs/`. Never manually edit files under `versioned_docs/`.
- **Broken links fail the build**: `docusaurus.config.js` sets `onBrokenLinks: 'throw'` — fix all broken internal links before merging.
- **Node ≥18 required**: Matches the CI environment (GitHub Actions uses Node 18).

## Deployment

Pushing to `develop` triggers `.github/workflows/pages.yml`, which runs `npm run build` and publishes the output to GitHub Pages automatically. No manual deploy step needed.
